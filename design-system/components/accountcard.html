Account card. Type × State. Each type shows different data, which is why this is one set and not four components: Bank Account adds the estimated monthly yield, Credit Card shows limit, debt, % used and the cut/payment dates, Savings shows the CDT maturity countdown, Cash has neither number nor rate. The account type is locked after creation — to reclassify, the account must be recreated. The card never needs to handle a type change. THE ACCOUNT COLOUR IS THE AVATAR, AND NOTHING ELSE. 2026-09-01: the full-width AccountBanner was removed. It was the card’s only colour and it sat directly above the amount, which is what docs/25-account-color.md §2 forbids in as many words — “cards, rows and amounts stay neutral… an identity colour that only ever appears inside a small circle never shares a surface with a number, so it cannot be mistaken for one.” That boundary is the whole reason twelve hues are safe in an app where cyan already means net, red means expense and amber means tax. The banner also contradicted the code, which has never drawn one. So the header now opens with an AccountAvatar (size=SM), which is the sanctioned carrier, followed by the account NAME and the favourite star. The account type is PLAIN TEXT in fg/account — a neutral slate, not the account’s hue — and it sits on the META line, between the currency badge and the number. CORRECTED 2026-09-02. Until today this description, docs/10-account-page.md §10 and the handoff all said the type sat “junto al avatar” in the header, with the name on a line of its own below. Dev built it on the meta line instead and asked. Dev is right, for a reason neither of us wrote down: the name is the account’s identity and the type is a classifier, so a header that leads with the classifier and demotes the identity to the second line has the hierarchy backwards. On the meta line the type also joins the other two classifiers it belongs with — currency and number — and the header stops competing for width. The name is Body/Small-Emphasis, one line, ellipsis. It truncates: “Bancolombia Ahorros” does not fit beside a 24px avatar and a star inside a 220px card. That is the shipped behaviour, not an oversight, and the sample content is long on purpose so the card is authored against the case that actually happens. That pairing arrived in two steps. Design first dropped the AccountTypeBadge’s leading icon, because the avatar already draws the type glyph and two identical icons side by side stated the same fact twice. Alfredo then removed the badge altogether on 2026-09-01: once the icon was gone, the outlined pill was a container around a word, and a chip that contains only its own label is a border pretending to be information. AccountTypeBadge now has NO consumer anywhere in the file. The type still reads as TEXT, which is the form that survives colour blindness and a screen reader — the glyph in the avatar is decorative and announced by nothing. Measured at 11px Medium: 6.92:1 on the default surface, 6.30:1 on selected, 10.99:1 Dark. Small text needs 4.5:1. BEFORE 2026-09-01 this description said the banner must not be “fixed”. It was written on 08-17, four days before the colour system, and the two decisions had been contradicting each other since. Alfredo settled it on 08-24: the doc wins. account/purple/accent is the canvas default on the master, not a decision — each account stores its own hue. The palette is twelve account/{hue}/accent + /surface pairs and the picker is AccountColorPicker. Colour lives on the account record; the design system never names an account.
