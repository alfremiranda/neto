Chip that identifies WHICH account a row belongs to. What KIND of account it is, is AccountTypeBadge’s job; the two answer different questions and can appear together. The dot carries the account’s accent. At runtime that fill comes from the USER’S DATA — each account stores a hue picked from account/{hue}/accent — so account/purple/accent here is a canvas default, not a decision. Do not “fix” it to a static token: an audit that repoints this to a fixed colour breaks user-chosen account colour. The body stays neutral on purpose (bg/account · border/subtle · fg/account). Only the dot carries hue, so a row with four chips does not become a colour chart. The dot sits on bg/account, NOT on the avatar tint, and that is a second background nobody checked until 2026-08-22: amber measured 2.91:1 there and green passed by 0.01. Both moved to rung 700 in light. Any new accent has to clear 3:1 against BOTH. NOT a component set, deliberately. It used to be one, with Color=Cyan|Purple|Green|Neutral standing in for account slots 1-4; those were renamed to slots, and then the slot model died when the hue became a user choice. What was left were two variant axes with exactly one option each — which is not variance, and would have extracted into code as Color=”Account 4”, a name meaning nothing. Dissolved 2026-08-17; 27 instances verified intact across four pages. Shipped in code 2026-08-22. The earlier note here said extraction was blocked until the exporter landed — it landed, and this is one of the components it unblocked.
