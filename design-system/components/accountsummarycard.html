The header of an account's own page: identity, the metadata, the headline figures, and the chart. Type × Device. It is NOT AccountCard. That one is the compact selectable tile in the grid — a control you press to choose an account. This is the detail of the account you are already inside, so it has no selected state and it carries the actions and figures the tile deliberately hides at size="sm". THE META IS ONE NODE PER FIELD, NOT ONE STRING. Alfredo, 2026-09-02: the metadata was already there but arrived as a single run of text, and it is separated now because that is how the data is handled. Each node is NAMED FOR ITS FIELD on the Account record, so the mapping is read off the layer name and never guessed: currency Account.currency every type — a CurrencyBadge instance, not text account-number Account.number every type except cash, which has none utilization debt / creditLimit credit cutoff Account.cutoffDay credit due Account.dueDay credit rate Account.rate savings · bank yield derived from rate savings · bank — a computed figure, not a stored field kind Account.savingsKind savings maturity Account.maturityDate savings, and only when the kind is a CDT THE META HAS TWO GROUPS, and which group a field belongs to is decided by one question: does it name a DATE the user has to act on? facts the plain run — currency, number, and the standing figures: utilization, kind, rate, yield schedule a chip: radius/16 on bg/surface, 1px account-summary-card/meta-chip/border, a calendar-days icon at size=S, then the dated fields — cutoff and due on a card, maturity on a CDT Alfredo drew the chip on Credit Card, 2026-09-02, and it carries to the other types by the same question. Savings has one dated field and gets a chip with maturity in it. Bank Account and Cash have none, so they have no chip and the facts run alone — an empty chip is not a quieter chip, it is a border round nothing. The chip earns its outline: Corte 4 · Pago 20 are the only two things on this card that are a deadline rather than a description, and putting a boundary round them is what says so without a word. The icon repeats it for anyone who does not read the boundary as meaning. Separators are Separator instances, not characters, so an absent field takes its separator with it instead of leaving a stranded middot. A field with no value hides; it does not render empty. The separator between the two groups belongs to facts, so a type with no chip has no trailing rule. THREE OF THESE ARE NEW and were missing from the card entirely, not just unsplit: currency — this app holds COP and USD and the card showed neither, so every figure on it was an amount without a unit. It is a CurrencyBadge instance and not a word, on Alfredo’s call: AccountCard already opens its meta with that badge, and the two cards describe the same account, so the currency has to look the same in both places. CurrencyBadge exists for exactly this — “used wherever an amount could be misread as the wrong currency”; kind — the savings vehicle, which the code already puts in its meta line and Figma did not have; maturity — a CDT's due date, which appeared nowhere on the account's own page. THE META ROW WRAPS WHEN IT HAS TO, and that is per variant rather than per Device — Alfredo set it on 2026-09-02. Savings on Desktop wraps because six facts plus the chip do not fit 640; Credit Card on Mobile does not, because three facts plus the chip fit 380. What drops to the second line is the chip, whole: a schedule chip that had to be squeezed or clipped would be worse than one on its own line. In code this is ONE declaration, not four: flex-wrap on the meta row, always. CSS wraps only when the content overflows, so the four behaviours Figma has to draw one variant at a time fall out of a single rule. Do not port the per-variant flag. Each type shows different data, which is why the metrics are a list built per type rather than a fixed set of slots: a cash account has no rate to report and a credit card's headline figure is a debt, not a balance.
