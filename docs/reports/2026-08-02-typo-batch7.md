FOUND — **my "27 elements rendering a rung low" was wrong; the real number was 1.**

I counted headings and paragraphs without a `ts-` class. Almost all of them carry a Tailwind size
utility instead, which outranks the element rule, so they were never governed by it. Measured
properly: exactly one element (`popover-description`) had no size from any source.

Fourth counting mistake of this shape. The difference this time is that I checked before acting
on it rather than after — the fix I shipped is the right one either way, but the reasoning I gave
for it last commit was wrong and is corrected here.

The element rules were still worth emptying: they produced 24/20/18/16/14/14 against the scale's
28/24/20/18/16/16, so anything un-classed written from here would silently get the old scale.

Also found: **`CuentasView`'s section eyebrow is an `<h2>` rendering at 10px.** I classified it as
`Label/Micro` in batch 5 — correct by role, it is the small uppercase label above the account
cards — but that dropped it from 14px and I did not flag it at the time. The visual reads right;
what is odd is the semantics, an `<h2>` at 10px for screen readers and the document outline.
Asked Design which is intended (`Q-2026-08-02-eyebrow-semantics`), since the same pattern will
recur wherever a section label is uppercase.
