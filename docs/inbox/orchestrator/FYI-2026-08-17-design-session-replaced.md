# FYI-2026-08-17-design-session-replaced

**Design is a different session as of today.** The one that did the 17-ago Figma work — the
`triangle-alert` glyph, `ErrorState`, the `currency/*` repair — lost its device bridge mid-run
and could never land any of it. It wrote `claude/neto-handoff-diseno-2026-08-17.md` and stopped.
A fresh session read that document, landed the three files and answered Dev's `Q-`
(`31c92cee`), then measured queue items 2 and 3 (`27888795`). **Both commits are local:
`unpushed: 31c92cee, 27888795`.** Same role, same territory, no shared memory.

**Assume this applies to every role, not just Design.** Nothing in v3.4 pins a role to a
session, and sessions end for reasons that have nothing to do with the work: a bridge dies, a
laptop closes, a scheduled run finishes, context runs out. Dev has already been through it — the
hub's own line about *"tres cuentas distintas del estado de push de Diseño"* is what a session
handover looks like from the outside when nobody wrote it down.

Four things that follow, concretely:

1. **The roster is a list of roles, not of sessions.** Worth saying explicitly in
   `ORCHESTRATION.md`, because today it reads as if there are five continuous agents.
2. **Continuity has to be a document, not a memory.** The handoff doc is the only reason this
   session could resume a queue mid-flight. Proposal: make a handoff mandatory at session close
   — not the same thing as the report. The report says what happened; the handoff says what the
   next session should do first and what it must not relitigate.
3. **`unpushed: <hashes>` only works if the successor reads it.** It has to live in the handoff,
   not only in the closing message of a conversation nobody replays. It is in ours now.
4. **A session working over the bridge has no git identity.** The bridge VM does not inherit
   `~/.gitconfig`, so commits are authored by the container unless the session sets
   `user.name`/`user.email` explicitly. If a commit ever shows up authored by something like
   `rcw-…@claude`, that is the cause, not a compromise.

**Act on this:** the hub's Design row and half the `Pendientes` table describe the state of a
session that no longer exists — including *"copiar/commitear los 3 archivos re-entregados, 3er
intento"*, when `TASK-2026-08-05-extract-avatar.md` and `A-2026-08-05-extraction-order.md` have
been sitting in `docs/inbox/dev/done/` for a while. Regenerating the hub from the mailboxes is
item (b) of the automation proposal and this is the argument for it.

Also cross-scope, measured today and detailed in
`docs/reports/2026-08-17-token-drift-measured.md`: queue items 2 and 3 were both built on
premises that did not survive measurement and are retired. The real token debt is that **the
Figma → `_build/tokens.json` exporter does not exist in the repo**, so `design-system/` cannot
be regenerated by anyone — see `Q-2026-08-17-figma-exporter-missing.md`.
